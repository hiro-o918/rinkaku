# Round 41

- Subject: PR #228 — container-aware edge matching for bare references
  (ADR 0068): splits `ExtractedSymbol`'s referenced names into bare and
  method-spec sets, reclassifies Go/TS interface and Rust trait method
  captures to `@reference.method`, and gates `collect_edges` so bare
  references only match container-less or same-container targets. Fixes
  a false edge where a bare Python call to a top-level class was
  attributed to an unrelated same-named method added in the same file.
- Protocol: two agents in parallel — one static reviewer (map-assisted
  and independent passes combined), one dynamic-verification pass. The
  implementing agent had already run its own e2e reproduction before
  review started.
- **Map delivery**: the static reviewer built `main` itself and ran
  `rinkaku --base origin/main` over the branch.
- **Map hit**: the map surfaced `graph.rs`'s
  `Node`/`collect_edges`/`push_matching_edges` as the highest-fan-in
  changed cluster and `ExtractedSymbol`/`collect_referenced_names` as
  signature-changed — exactly the two files carrying the substantive
  logic amid ~54 mostly-mechanical field-addition files. Attention
  allocation worked as designed.
- **Map miss**: the round's main should-fix — reclassifying interface/
  trait method-spec captures to `@reference.method` routes them through
  `is_ubiquitous_method_name`'s stoplist (ADR 0064), silently dropping
  spec-to-implementation edges for names like `get`. The interaction
  has no footprint on the signature surface; it emerged only from the
  static pass cross-reading the ADR's Consequences section and then
  running before/after binaries. The dynamic pass sharpened the
  severity gradient: TypeScript is far more exposed (idiomatic
  lowercase `get`/`set`/`has`/`delete`/`clear` all sit on the
  stoplist) than Go (exported methods are capitalized; the stoplist is
  all-lowercase), a distinction the ADR originally glossed over.
  Resolved by pinning the tradeoff with a regression test, amending the
  ADR's exposure wording, and opening issue #230 to scope the stoplist
  to receiver-call captures.
- **Dynamic pass**: a five-language scenario matrix run against built
  binaries — the Python reproduction verified side by side against a
  `main` build that still exhibits the false edge; Rust receiver calls,
  Go and TS interface specs all kept their cross-container edges; a
  capitalized Go `Get()` confirmed immune to the stoplist. Non-TTY
  stdin/stdout, empty diff, all four formats, and conflicting flags
  produced no panics; JSON output showed no internal-field leakage.
- Severity summary: 0 blockers, 2 should-fix (the stoplist exposure
  above; a stale test name still saying `referenced_names` after its
  assertions moved), 1 nit (`Node::container` compares unqualified by
  path across files — strictly narrower than pre-PR behavior, noted
  for the record). All addressed before merge.
- Takeaway: reclassifying a capture changes which downstream filters
  apply to it — the regression lived in the interaction between new
  routing and an old stoplist, a class of defect the signature map
  cannot represent. ADR-text cross-reading plus before/after binary
  runs caught it; the cheap side-by-side old/new binary comparison on
  the motivating fixture also proved both the bug and the fix in one
  step.
