# Round 42

- Subject: GitHub stacked PR support (ADR 0075): stack discovery via
  GraphQL, per-layer SHA resolution before the TUI opens, a
  cursor-following background prefetch cache, `gt`/`gT` layer
  navigation with a `PR #N k/n` status prefix, and PR-numbered
  annotations exported per PR.
- Protocol: three agents in parallel after a skeleton-first build —
  one map-assisted static pass, one independent static pass, one
  dynamic-verification pass driving the built binary through a pty
  against a real five-layer stack in a private repository. The first
  independent and dynamic agents died mid-run (host sleep); the dynamic
  logs survived and were read by hand, the independent pass was rerun.
- **Map delivery**: the static reviewer ran a trusted `main` build over
  the branch (`rinkaku --base main`) from inside the worktree.
- **Map hit**: the high-fan-in cluster (`Slot`, `StackEntry`,
  `ReviewPorts`, `ReviewState`, `StackPosition`) pointed straight at
  the worker/driver seam, and the reviewer cleared the
  `claim_next`/`wait_ready` deadlock question in one pass. The map's
  new-test list for `cli.rs` exposed the missing `--no-stack` test by
  pattern gap.
- **Map miss**: a stale doc comment still naming the abandoned `p`/`P`
  binding — the map does not diff comments; plain reading against the
  ADR caught it. The independent pass found the two defects with no
  signature footprint: `run_stack` skipping its mouse-capture postamble
  on an `Err` from the event loop, and a mid-batch review-post failure
  hiding which PRs had already been posted (a retry would double-post).
- **Dynamic pass**: the navigation scenario passed end to end
  (`PR #… 1/5` → `gt` ×4 → `5/5`, clamped at both ends, splash
  `Analyzing PR #N (k/n)…` shown only while a layer was still
  in flight, annotations keeping their own PR number across switches,
  clean quit, non-TUI formats and a non-stacked PR unchanged). The
  top-layer scenario then failed with "fetched PR #N head does not
  match `gh`'s reported head" — the fetched SHA belonged to the layer
  *above*. Cause: the agent had two rinkaku processes fetching in the
  same clone at once, and `fetch_pr_head`'s `git fetch` →
  `git rev-parse FETCH_HEAD` pair is not atomic across processes. The
  single-PR path has carried the same race since ADR 0007; a stack
  session's run of consecutive fetches merely widened the window
  enough to hit. Fixed by fetching all layers in one multi-refspec
  call into `refs/rinkaku/pull/<N>/head` and rev-parsing the named
  refs; the top-layer scenario passed on rerun.
- Severity summary: 0 blockers from the static passes (one stale
  doc comment), 2 should-fix (postamble on error; partial-post
  reporting), 1 dynamic finding (the `FETCH_HEAD` race), 2 nits left
  as-is (combined status-line width with optional suffixes is a
  pre-existing gap; a Source-screen no-op test for `gt`). All
  should-fixes and the race addressed before the PR.
- Takeaway: the dynamic pass's best finding again came from something
  no reviewer would have written into a scenario — an accidental
  concurrent run. Concurrency with *another instance of the same tool*
  is a failure mode worth adding to the dynamic checklist explicitly,
  alongside non-TTY and empty input.
